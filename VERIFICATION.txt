V2RAY BUGFIX
-------------

Статически подтверждено:

- ConnectivityManager получается только через application context Restorer;
- diagnostic log содержит contextPackage=com.mitv.accessibilityrestorer на ТВ;
- VPN state представлен ACTIVE / INACTIVE / UNKNOWN;
- SecurityException retry: максимум 3 попытки;
- пауза между retry: 100 ms;
- лог содержит attempt=N/3, permissionGranted и exception;
- после исчерпания retries логируется VPN state remains UNKNOWN;
- UNKNOWN разрешает SEND_ONCE_FALLBACK_STOPPED только после повторного
  FLAG_STOPPED=true readback;
- stopped=false + UNKNOWN завершается без blind toggle;
- непосредственно перед trigger снова проверяется VPN;
- widget action и component не изменены;
- в V2RayVpnAssist имеется ровно один вызов sendTrigger и один вызов
  Context.sendBroadcast;
- poll после trigger: 250 ms;
- timeout после trigger: 5000 ms;
- grace для stopped=false: 2000 ms.

Intent:

action=com.v2raytun.android.action.widget.click
component=com.v2raytun.android/.receiver.WidgetProvider1x1
flag=Intent.FLAG_INCLUDE_STOPPED_PACKAGES

Устаревшая строка "ACCESS_NETWORK_STATE unavailable" удалена.

FIRST RUN / INSTALLER
---------------------

ControlActivity содержит TV-focusable кнопки:

- Завершить настройку
- Проверить снова
- Диагностика
- Восстановить сейчас

SetupStatus проверяет:

- WRITE_SECURE_SETTINGS через checkSelfPermission на API 23+;
- пакеты и AccessibilityService Button Mapper/Projectivy;
- optional TorrServe/GlobalTorrService;
- optional v2RayTun.

SetupState хранит setup_completed=true. Итоговый setupComplete всегда требует
реально выданного WRITE_SECURE_SETTINGS и наличия двух основных компонентов.
Optional integrations не блокируют завершение.

INSTALL.cmd статически проверен на workflow:

1. adb.exe в PATH.
2. adb start-server.
3. Ровно одно устройство со state=device.
4. adb install -r APK рядом со скриптом.
5. pm grant WRITE_SECURE_SETTINGS.
6. dumpsys readback granted=true.
7. am start ControlActivity.
8. success message и pause.

При INSTALL_FAILED_UPDATE_INCOMPATIBLE скрипт только показывает команду
adb uninstall и не выполняет её.

INSTALL.cmd НЕ содержит и НЕ выполняет запись start_3rd_app.

start_3rd_app внутри APK теперь строго read-only:

- ALREADY_ARMED
- MISSING_UNARMED
- READ_FAILED

DEX не содержит Settings.System.putString или статусов WRITE_REQUIRED /
WRITE_SUCCESS / WRITE_FAILED. APK не создаёт vendor setting.

COLD BOOT REGRESSION
--------------------

Следующие исходники byte-for-byte совпадают с commit
817847b92235aaeac5364e63c35c80fa005baf7e:

- BootReceiver.java
- RestoreReceiver.java
- BootSessionState.java
- AccessibilityRestorer.java
- DirectBootContext.java
- RecoveryState.java
- MainActivity.java

RecoveryEngine.java отличается от исходного commit только VERSION_CODE 9 -> 10.
Его runColdBoot(), Direct Boot, BOOT_COUNT, lastCompletedBootCount, early boot
2500 ms, one-shot fallback alarm 10000 ms, lightweight recovery и final
Projectivy launch не изменены.

VendorStartApp API/calls сохранены, но helper намеренно переведён в read-only,
чтобы выполнить требование не записывать start_3rd_app из APK. Это не добавляет
в cold boot новых фаз, задержек, TorrServe, VPN или setup UI.

В BootReceiver, RestoreReceiver, AccessibilityRestorer и MainActivity нет ссылок
на TorrServeTarget, V2RayVpnAssist, SetupState или SetupStatus.

ФИЗИЧЕСКАЯ ПРОВЕРКА, КОТОРУЮ ЕЩЁ НУЖНО ВЫПОЛНИТЬ
-------------------------------------------------

Сначала удалить переживающий uninstall vendor setting:

adb shell settings delete system start_3rd_app
adb shell settings get system start_3rd_app

Ожидается: null

Затем:

adb uninstall com.mitv.accessibilityrestorer

Установить через INSTALL.cmd и убедиться, что скрипт не создаёт setting:

adb shell settings get system start_3rd_app

Ожидается: null

Выполнить минимум 3 цикла Sleep -> 30 sec -> Wake и отдельно минимум 5 STR для
v2RayTun. Нужна проверка обычного пути SEND_ONCE -> CONNECTED и, если Xiaomi
воспроизведёт SecurityException, пути:

SecurityException -> retries -> UNKNOWN -> stopped=true
-> SEND_ONCE_FALLBACK_STOPPED -> CONNECTED

Также проверить cold boot, dumpsys accessibility, Binding/Crashed, процессы
TorrServe/torrserver, VPN transport/tun0 и Home -> Projectivy без Xiaomi flicker.
