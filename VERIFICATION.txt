POST_BOOT_OPTIONAL GATE
-----------------------

Статически подтверждено:

1. BootReceiver фиксирует Android BOOT_COMPLETED_RECEIVED по текущему BOOT_COUNT
   в Device Protected Storage до прежней проверки fallback-сессии.
2. Успешный runColdBoot после записи boot completion marker вызывает тот же
   maybeStartPostBootOptionalRecovery(expectedBootCount).
3. Gate требует одновременно current BOOT_COUNT, RecoveryState boot-completed
   marker и BOOT_COMPLETED_RECEIVED для того же BOOT_COUNT.
4. Порядок событий не важен: первый вызов только сохраняет условие, второй
   запускает worker после появления обоих условий.
5. last_post_boot_optional_boot_count записывается commit() до старта worker.
6. Дополнительный in-memory bootCount marker закрывает конкурентный повтор в
   одном процессе.
7. Повторный broadcast, Activity callback или повторный gate check видит
   alreadyExecuted=true и не запускает второй worker.
8. Worker является отдельным Thread и не участвует в уже записанном core
   SESSION FINISH/fullSuccess.

TORRSERVE POST-BOOT
-------------------

Статически подтверждено:

- сначала проверяется ru.yourok.torrserve;
- затем проверяется GlobalTorrService и BIND_ACCESSIBILITY_SERVICE;
- отсутствие даёт SKIPPED_NOT_INSTALLED или SKIPPED_COMPONENT_UNAVAILABLE;
- текущий enabled_accessibility_services читается как raw String;
- существующие tokens не удаляются, не нормализуются и не сортируются;
- ComponentName-сравнение предотвращает дубликат полного или сокращённого token;
- если target уже присутствует, возвращается ALREADY_ENABLED без putString;
- иначе к исходной строке добавляется только один GlobalTorrService token;
- успешный putString даёт RECOVERED, ошибка остаётся локальным FAILED;
- нет TorrServe Activity, BCReceiver, custom broadcast или explicit unstop в
  post-boot реализации.

V2RAY POST-BOOT
---------------

Статически подтверждено:

- сначала проверяется package com.v2raytun.android;
- затем проверяется receiver WidgetProvider1x1;
- отсутствие даёт SKIPPED_NOT_INSTALLED или SKIPPED_COMPONENT_UNAVAILABLE;

- grace: 2000 ms, poll: 250 ms, timeout: 5000 ms;
- в исходнике одна точка вызова sendTrigger и один Context.sendBroadcast;
- action/component/FLAG_INCLUDE_STOPPED_PACKAGES не изменены;
- stopped=false + VPN=UNKNOWN завершается без blind toggle;
- UNKNOWN + подтверждённый stopped=true допускает SEND_ONCE_FALLBACK_STOPPED;
- optional worker ожидает результат helper только для итогового advisory log;
  core Projectivy/fullSuccess его не ждут.

OPTIONAL INDEPENDENCE
---------------------

На уровне ветвления проверены четыре конфигурации:

A. TorrServe=yes, v2RayTun=yes
B. TorrServe=yes, v2RayTun=no
C. TorrServe=no,  v2RayTun=yes
D. TorrServe=no,  v2RayTun=no

TorrServe выполняется в собственном try/catch. После любого его статуса или
RuntimeException код переходит к независимой проверке v2RayTun. Optional statuses
не входят в coreRecoverySuccess, bootMarked, fullSuccess или STR success.

--------------

- ALL_INITIAL: 2500 ms

- MAPPER: 2500 ms
- ALL_FINAL: 1500 ms

Сохранены black RecoveryCover, Button Mapper/Projectivy invisible unstop,

- pause: 1000 ms

Отсутствующий TorrServe package/component исключает его из ALL_FINAL и не меняет
core STR success.

MANUAL UI ROUTING
-----------------

Статически подтверждено:

- Manifest launcher entry остаётся на MainActivity;
- BOOT_PENDING обрабатывается до любой попытки открыть UI;
- non-interactive запуск фиксирует strRecoveryRequired и сохраняет wake/STR путь;
- SCREEN_ON и STR_BOOT_COMPLETED фиксируют strRecoveryRequired;
- active RecoveryState session не маршрутизируется в пользовательский UI;
- только STR_READY + interactive + no STR/wake marker + no active session даёт:
  MAIN DECISION mode=USER_UI reason=no_recovery_required;
- затем выполняются startActivity(ControlActivity) и finish MainActivity;
- user route не вызывает RecoveryCover, STR reset или Projectivy launch.
