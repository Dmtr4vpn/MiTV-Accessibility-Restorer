=======================================================

Дата локальной проверки: 2026-09-04

------

V2RAY BUGFIX
-------------

Статически подтверждено:

- ConnectivityManager получается только через application context Restorer;
- diagnostic log содержит contextPackage=com.mitv.accessibilityrestorer на ТВ;
- VPN state представлен ACTIVE / INACTIVE / UNKNOWN;
- SecurityException retry: максимум 3 попытки;
- пауза между retry: 100 ms;
- лог содержит attempt=N/3, permissionGranted и exception;
- после исчерпания retries логируется VPN state remains UNKNOWN;
- UNKNOWN разрешает SEND_ONCE_FALLBACK_STOPPED только после повторного
  FLAG_STOPPED=true readback;
- stopped=false + UNKNOWN завершается без blind toggle;
- непосредственно перед trigger снова проверяется VPN;
- widget action и component не изменены;
- в V2RayVpnAssist имеется ровно один вызов sendTrigger и один вызов
  Context.sendBroadcast;
- poll после trigger: 250 ms;
- timeout после trigger: 5000 ms;
- grace для stopped=false: 2000 ms.

Cold boot post-VPN статически подтверждён:

- core `SESSION FINISH` и boot completion marker выполняются до VPN assist;
- вызов разрешён только при fullSuccess=true;
- после `SESSION FINISH` вызывается существующий асинхронный
  V2RayVpnAssist.start(context, session, source=COLD_BOOT_POST_VPN);
- Projectivy final launch и весь core завершаются до запуска VPN worker;
- VPN результат не участвует в fullSuccess и не меняет boot completion marker;
- отдельные логи содержат COLD BOOT POST VPN scheduled/started/FINISH;
- итог FINISH содержит vpnAssist, vpnTriggerSent и vpnDetected;
- V2RayVpnAssist.run(), sendTrigger и правила VPN decision byte-for-byte не
  изменены относительно commit 5202f9cc861806a1ed92a433de208a2dc8b77c40;
- дополнительная post-boot задержка не добавлена.

Intent:

action=com.v2raytun.android.action.widget.click
component=com.v2raytun.android/.receiver.WidgetProvider1x1
flag=Intent.FLAG_INCLUDE_STOPPED_PACKAGES

Устаревшая строка "ACCESS_NETWORK_STATE unavailable" удалена.

FIRST RUN / INSTALLER
---------------------

ControlActivity содержит TV-focusable кнопки:

- Завершить настройку
- Проверить снова
- Диагностика
- Восстановить сейчас

SetupStatus проверяет:

- WRITE_SECURE_SETTINGS через checkSelfPermission на API 23+;
- пакеты и AccessibilityService Button Mapper/Projectivy;
- optional TorrServe/GlobalTorrService;
- optional v2RayTun.

SetupState хранит setup_completed=true. Итоговый setupComplete всегда требует
реально выданного WRITE_SECURE_SETTINGS и наличия двух основных компонентов.
Optional integrations не блокируют завершение.

INSTALL.cmd статически и через fake ADB проверен на workflow:

1. Локальный adb\adb.exe с fallback на PATH.
2. adb start-server и автоматический выбор единственного device.
3. Диалог IP/port/pairing только при отсутствии подключения.
4. Последовательный перебор всех install\*.apk без промежуточных pause.
5. Чтение package/versionCode из бинарного AndroidManifest.xml каждого APK.
6. Package отсутствует -> adb install.
7. Installed versionCode меньше -> adb install -r.
8. VersionCode равен -> SKIP_SAME_VERSION без adb install.
9. Installed versionCode больше -> SKIP_NEWER_VERSION без downgrade.
10. После любого skip выполняются pm grant, readback и am start ControlActivity.
11. Общий результат и один перезаписываемый INSTALL-LOG.txt.

При несовместимой подписи INSTALL.cmd не выполняет uninstall автоматически.

INSTALL.cmd НЕ содержит и НЕ выполняет запись start_3rd_app.

start_3rd_app внутри APK теперь строго read-only:

- ALREADY_ARMED
- MISSING_UNARMED
- READ_FAILED

DEX не содержит Settings.System.putString или статусов WRITE_REQUIRED /
WRITE_SUCCESS / WRITE_FAILED. APK не создаёт vendor setting.

COLD BOOT REGRESSION
--------------------

Следующие исходники byte-for-byte совпадают с базовым commit
5202f9cc861806a1ed92a433de208a2dc8b77c40:

- BootReceiver.java
- RestoreReceiver.java
- BootSessionState.java
- AccessibilityRestorer.java
- DirectBootContext.java
- RecoveryState.java
- MainActivity.java
- RecoveryCoverActivity.java
- TorrServeTarget.java
- TargetUnstopper.java

RecoveryEngine.java отличается от базового commit только VERSION_CODE 10 -> 11
и условным post-VPN вызовом после уже записанного SESSION FINISH. Direct Boot,
BOOT_COUNT, lastCompletedBootCount, early boot 2500 ms, one-shot fallback alarm
10000 ms, lightweight recovery, Projectivy final launch и boot marker не изменены.
STR tail RecoveryEngine byte-for-byte совпадает с базовым commit.

VendorStartApp и read-only advisory start_3rd_app не изменены. Пустое значение
остаётся MISSING_UNARMED и не считается ошибкой.

В BootReceiver, RestoreReceiver, AccessibilityRestorer и MainActivity нет ссылок
на V2RayVpnAssist. Post-boot invocation локализован в RecoveryEngine после
успешного SESSION FINISH.

STR REGRESSION
--------------

RecoveryEngine STR timing profile не изменён:

- interactive settle: 500 ms
- ALL INITIAL: 2500 ms
- BASE: 1500 ms
- MAPPER: 2500 ms
- ALL FINAL: 1500 ms

Conservative retry не изменён:

- retry pause: 1000 ms
- ALL INITIAL: 4000 ms
- BASE: 3000 ms
- MAPPER: 3000 ms
- ALL FINAL: 3000 ms
- максимум 2 attempts

Button Mapper/Projectivy invisible unstop, black RecoveryCover, final Projectivy
и TorrServe только в ALL FINAL не изменены. Двухаргументный STR-вызов
V2RayVpnAssist сохранён и делегирует прежней логике с source=null; VPN по-прежнему
не задерживает final Projectivy.

ФИЗИЧЕСКАЯ ПРОВЕРКА, КОТОРУЮ ЕЩЁ НУЖНО ВЫПОЛНИТЬ
-------------------------------------------------

Обновить установленный versionCode 10 через INSTALL.cmd. Ожидается сравнение
10 < 11 и обычный adb install -r с тем же сертификатом. Затем проверить:

adb shell settings get system start_3rd_app
adb shell settings get secure enabled_accessibility_services
adb shell settings get secure accessibility_enabled

start_3rd_app может быть пустым/MISSING_UNARMED; Restorer не должен его записывать.

Выполнить один настоящий cold boot. Ожидаемый core путь остаётся прежним:

EARLY_BOOT -> accessibility success -> Projectivy launch success
-> SESSION FINISH success

После него должны появиться:

COLD BOOT POST VPN assist scheduled
COLD BOOT POST VPN assist started
V2RAY packageInstalled=...
V2RAY stoppedBefore=...
VPN BEFORE active=...
V2RAY VPN trigger decision=...
COLD BOOT POST VPN FINISH, vpnAssist=CONNECTED|ALREADY_ACTIVE|...

Проверить:

adb shell dumpsys accessibility
adb shell dumpsys connectivity
adb shell ps -A
adb shell "logcat -d | grep -iE 'MiTVRestorer|accessibilityrestorer|AndroidRuntime'"

Финально нужны Projectivy foreground, Button Mapper/Projectivy Bound,
Binding={}, Crashed={}, V2RayVpnService active, VPN CONNECTED, InterfaceName=tun0
и работающий YouTube без ручного запуска v2RayTun. TorrServe cold boot не менялся.
